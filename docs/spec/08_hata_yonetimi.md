# 8. Hata yönetimi

**8.1** `TR_kw_try { ... } TR_kw_catch ad { ... }`: dene bloğunda hata olursa yakala bloğu, hata mesajı `ad` değişkenine bağlanarak çalışır. Ad verilmezse `TR_ctx_error` kullanılır; `yakala (ad)` biçimi de geçerlidir.

```tr
//! tr kodlu 3 dil=tr
TR_kw_try { TR_kw_throw "patladı" } TR_kw_catch { TR_fn_print(TR_ctx_error) }
```

**8.2** `TR_kw_throw ifade` bir hata başlatır; değer metne çevrilir ve yakalayan değişken her zaman `TR_type_String`dir (`TR_kw_throw {"kod": 5}` → `` `{"kod": 5}` ``).

**8.3** Çalışma zamanı hataları (sıfıra bölme, tanımsız ad, tip uyuşmazlığı...) da yakalanabilir; mesajları `Satır N:` ile başlar. Yakalanan hatanın metni programın değeridir: onu yakalayan dosyanın dilinde kurulur, içindeki tip adları ve değerlerle (İngilizce dosyada `Line N: ... Bool (true) given`; değer metni kuralı, 3), hata başka bir dosyada oluşmuş olsa da. Yakalanmayan hata fonksiyon çağrılarından yukarı yayılır ve programı konum ve kod çerçevesiyle durdurur; ekrandaki bu ileti görüntüdür, kişinin dilindedir (`TR_DIL`). Kesme isteği (Ctrl+C, bkz. 1.5) bir hata değildir, yakalanmaz.

**8.4** Hata ve uyarılar terminale yazılırken (komut satırının hata çıktısı, `tr test` raporu, eşzamanlı görev hataları) denetim karakterleri görünür biçimde yazılır: `\x1b`, `\x07`, `\u009b` gibi; satır sonu ve sekme korunur. Böylece iletiye giren dış veri (bir dosya adı, bir JSON değeri) terminali silemez, metni gizleyemez. Yakalanan hatanın metni değişmez (`dene/yakala` ile alınan metin olduğu gibidir); programın kendi çıktısı (`TR_fn_print`) da değişmez, orada renk kullanmak programın seçimidir. Karşılaştırma: Python ve Go hata metnini olduğu gibi yazar; git ve systemd dışarıdan gelen metni terminale yazmadan önce kaçırır.

**8.5** Katalog iletisiyle hata: `TR_kw_throw TR_type_Message(H6903, -1)` ya da `TR_fn_assert(koşul, TR_type_Message(H6903, -1))` hatayı iletinin kodu ve değerleriyle fırlatır (`TR_type_Message`: kod, ardından kataloğun tanımındaki sırayla değerler; kod tanımlı olmalı, değer sayısı tanımla aynı olmalı, aksi `TR_type_Message` kurulurken hata verir). İletinin metni katalogdan kurulur ve iki yerde okunur: yakalanan hata yakalayan dosyanın dilinde (8.3), yakalanmayan hata kişinin dilinde (`TR_DIL`). Kitaplığın hata metinleri böyle yazılır, bu yüzden kitaplık hangi dilde yazılmış olursa olsun hatası okuyanın dilinde çıkar; kitaplığın kendi adları iletide katalog tarafından o dilin adıyla yazılır. Düz metin `TR_kw_throw "..."` kullanıcı programları içindir ve aynen kalır. `TR_fn_error_code(f)` `f`'yi çalıştırır ve fırlayan iletinin kodunu `TR_type_String` olarak (`"H6903"`) verir, hata yoksa `TR_kw_none`: testler iletinin metnini değil kodunu sınar (`TR_fn_assert_equal("H6903", TR_fn_error_code(() => ...))`), ileti yeniden yazılınca kırılmaz. `TR_fn_error_code`, iletinin neden yuvasından inerek en içteki nedenin kodunu verir. Karşılaştırma (2026-10-26): Python gettext, Swift `String(localized:)` ve Go `x/text` kaynak metni anahtar yapar (metin değişince çeviri düşer, geliştiricinin dili ayrıcalıklı olur); Fluent (`get_message("kimlik")`) ve Java ResourceBundle açık kimlik kullanır, TR'nin H kodları da açık kimliktir; seçim ikinci aileden.
